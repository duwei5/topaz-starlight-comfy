# Topaz 星光2.6 超分工作流 — 使用说明

> 配套文件：`Topaz星光25超分_模板.json`（工作流） + `ComfyUI/topaz_engine/`（离线引擎包）
> 版本：2026-08 · 引擎：Topaz NeuroServer（星光 SLP-2.5）

---

## 一、这是什么

把 Topaz 的星光 2.6 视频增强模型**搬进 ComfyUI** 的自定义节点工作流。
ComfyUI 生成/导入的视频帧 → 星光 2.6 增强放大 → 输出成品视频（音频自动保留）。

```
[LoadVideo 选视频] ──帧──> [星光2.6超分] ──增强帧──> [VideoCombine 输出mp4]
        └──────────────── 音频自动旁路 ────────────────┘
```

## 二、快速开始

1. 确认 `ComfyUI/topaz_engine/` 存在（18GB 引擎包，含模型权重）
2. 重启 ComfyUI，加载 `Topaz星光25超分_模板.json`
3. 在 **LoadVideo** 节点点「选择文件」选视频；`force_rate` 设为视频真实帧率
4. 先设 `frame_load_cap = 10`（只跑 10 帧）试通，确认输出正常后改回 `0`（全部帧）
5. 星光节点保持默认参数（放大倍数 2、增强强度 1.0），点运行
6. 成品在 `ComfyUI/output/TopazStarlight/` 目录，音频已自动带上

> 首次运行会加载模型（约 30~60 秒），之后每帧 3~5 秒——慢是星光 2.6 的正常速度（7B 扩散模型）。模板里自带一张说明卡片（MarkdownNote），关键参数都写在上面。

## 三、模板工作流节点详解

模板共 4 个节点、3 条连线：

```
[LoadVideo] ──IMAGE──> [星光2.6超分] ──IMAGE──> [VideoCombine]
      └──────────────────── AUDIO ────────────────────┘
```

### 3.1 LoadVideo（视频输入，VHS 节点）

| 参数 | 填什么 |
|------|--------|
| 选择文件 | 点按钮选视频；模板已清空，等你来选 |
| `force_rate` | **视频真实帧率**（右键视频文件→属性→详细信息可看）。填错会导致帧率判断错误，输出时快时慢 |
| `frame_load_cap` | 试跑填 `10`；正式跑填 `0`（全部帧） |
| `skip_first_frames` / `select_every_nth` | 默认 0 / 1，通常不用动 |

> 常见帧率速查：电影 24、B站/AI视频 16~24、手机录像 30、慢动作 60。

### 3.2 星光2.6升格（本节点）

| 参数 | 默认 | 说明 |
|------|------|------|
| 模型 | 星光 2.6 | 星光2.6=1.7.1引擎的2.6权重（官方换代）；Astra系列需≥9帧 |
| 显存上限 | 96.0 GiB | 神经服务器显存上限（0.1 步进，上限 96，是"允许上限"：引擎按需分配，不强制占满）。**分享给他人默认 96=不设限**，各硬件自行下调：16G卡建议14（防驱动借共享内存变慢），吃紧降到12/10；大显存卡(24G/32G/48G/96G)可拉满 |
| 放大倍数 | 2.00 | 支持两位小数（1.78/2.67，参考表精确倍率）；1.00=只增强不放大；内部对齐偶数像素 |
| 帧率 | 24 | 和 LoadVideo 的 `force_rate` 一致 |
| 增强强度 | 1.0 | 0.7 柔和保真 / 1.0 默认 / 1.3 细节最猛 |
| 输入质量 | 14 | 中间编码质量，正常不用动；有块状伪影时降到 8 |
| GPU选择 | Auto (自动) | 自动识别多显卡。Auto=ComfyUI 主卡(cuda:0，与旧默认一致)；可手动选任意一张。超分用 CUDA 枚举（本机 cuda:0=4070TiS、cuda:1=4060Ti）。单卡机器只有一个选项，无需理会 |

**模型说明**：
- **星光 2.6**（1.7.1 引擎）：官方换代——1.7.1 的"星光 2.6"条目即 **2.6 权重**（和 GUI 行为一致），画质最佳，短帧无限制，最稳
- **Astra / Astra HQ / Astra Sharp**（1.7.1 引擎）：变体模型，**必须 ≥9 帧**（引擎短视频路径有缺陷，节点已自动拦截并提示）
- **Astra Fast**（1.7.1 引擎）：快速版，依赖 tvai_up 滤镜 + nyx-3 模型，**引擎包内需 Intel 核显（QSV）**，无核显机器上 GUI 可用、节点暂不可用

（完整讲解见「四、节点参数详解」）

### 3.3 VideoCombine（视频输出，VHS 节点）

| 参数 | 默认 | 说明 |
|------|------|------|
| `frame_rate` | 24 | 输出视频帧率，和输入一致 |
| `filename_prefix` | `TopazStarlight/` | 输出到 `ComfyUI/output/TopazStarlight/` 目录，按需改 |
| `format` | `video/h264-mp4` | h264 + mp4，通用兼容 |
| `crf` | 19 | 输出压缩质量，越小越清晰；18~23 都可用 |
| `save_output` | 开 | 关闭则只预览不落盘 |

> **音频**：模板已把 `LoadVideo.audio → VideoCombine.audio` 连好，视频轨走星光、音频轨原样旁路，成品自带声音。别删这条线。

> **⚠️ 保存慢？** VideoCombine 默认 `video/h264-mp4` 走 **CPU libx264 编码**，且逐帧 Python 转换，704×576 只有 ~53fps（7476 帧要 2.4 分钟）。两个解法：
> 1. 把 `format` 换成 **`video/nvenc_h264-mp4`**（VHS 自带 GPU 编码），提到 ~69fps（1.8 分钟）；
> 2. 或直接换成下面的 **Topaz 视频输出** 节点，实测 196fps（约 **38 秒**），而且引擎自带 ffmpeg，分享给别人也能用。

### 3.4 Topaz 视频输出（快保存，本节点，推荐）

比 VideoCombine 快 3~4 倍的原生保存节点（整批 torch 转换 + 大块写管道 + GPU h264_nvenc）。

| 参数 | 默认 | 说明 |
|------|------|------|
| `图像` | - | 接星光/插帧输出（IMAGE） |
| `帧率` | 30 | 和前面的帧率一致（插帧 60 就填 60） |
| `输出目录` | `TopazStarlight` | 存到 `ComfyUI/output/{此目录}/`，可含子路径如 `项目/片段` |
| `日期子文件夹` | 开 | 开启则自动建当天子文件夹 `output/{输出目录}/{2026-09-03}/` |
| `文件名前缀` | `Topaz` | 文件名前缀，如 `Topaz_20260903_153045.mp4` |
| `命名` | 前缀+时间戳 | **前缀+时间戳**=每次唯一不覆盖；**自动编号**=`前缀_00001` 递增 |
| `编码` | GPU (h264_nvenc 快) | GPU=NVENC 硬件编码；CPU=libx264 兜底（自动回退） |
| `音频`（可选） | - | 接 LoadVideo 的 audio，成品自动合并声音 |

**默认输出示例**：`ComfyUI/output/TopazStarlight/2026-09-03/成品_20260903_153045.mp4`

- 实测：704×576 GPU 编码 **196fps**，7476 帧约 38 秒；CPU 兜底 76fps。
- GPU 编码不可用时自动回退 CPU，不会报错。
- 找不到 ffmpeg 时优先用引擎包自带的全功能 ffmpeg，分享给别人也开箱即用。

## 五、节点参数详解


### 放大倍数（scale，1.0~4.0，步进 0.1，默认 2.0）

- 输出尺寸 = 输入尺寸 × 倍数，**支持小数**（1.2 / 1.5 / 1.8 都行）
- `1.0` = 不放大，**纯增强**（去噪、修细节，尺寸不变）
- 2.0 是画质与速度的平衡点；3~4 倍更慢，且超过模型训练范围的放大收益有限
- 小数倍实测可用（模型按比例重绘）；内部会把输出尺寸取整并对齐到偶数像素（h264 编码要求），实际倍率与输入相差 <1%
- 想精确到某分辨率（如 4K=3840×2160）：放大倍数 = 目标宽 ÷ 源宽，如 1080p 源 × 1.78

### 帧率（fps，默认 24）

- **必须与视频实际帧率一致**（以 LoadVideo 的 `force_rate` 为准）
- 只影响中间编码与进度计算，不影响最终输出帧率

### 增强强度（enhancement_strength，0.5~1.5，默认 1.0）

星光 2.6 是**生成式增强**——不是锐化滤镜，而是重新绘制细节。
本参数控制模型"敢不敢大胆重画"。

| 数值 | 风格 | 适用场景 |
|------|------|----------|
| 0.7 | 柔和 | 人脸、皮肤、文字等怕画歪的内容 |
| 1.0 | 默认 | 通用平衡 |
| 1.3 | 细节最猛 | 想突出纹理质感（注意可能过度锐化、放大噪点） |

> 记忆法：增强强度 = 星光"敢不敢画"。决定风格。
> 对速度几乎无影响。

### 输入质量（qp，0~40，默认 14）

**这不是模型参数**，而是本节点的"搬运损耗"：
ComfyUI 的帧需要先进成临时 h264 视频再喂给星光，qp 就是这个中间压缩的强度。

| 数值 | 效果 |
|------|------|
| 0~8 | 近乎无损，但临时文件巨大、编码慢，收益不可见 |
| 14（默认） | 视觉近无损的甜点位，**正常不用动** |
| 28+ | 压缩伪影会被星光"脑补"放大——最糟情况 |

> 记忆法：输入质量 = 星光"看得清不清"。决定上限。
> qp 越小越无损（注意方向和其他参数相反）。

## 六、插帧/补帧节点（Topaz 插帧 Apollo/Aion/Chronos）

第二个节点：**把视频从 X fps 提升到 Y fps**（补流畅、做慢动作）。和星光节点互补——
星光负责"清晰度/分辨率"，插帧节点负责"流畅度/帧率"。

```
[LoadVideo 选视频] ──帧──> [Topaz 插帧] ──帧──> [VideoCombine 输出mp4]
        └──────────────── 音频自动旁路 ────────────────┘
```

### 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| 模型 | Apollo (推荐) | Apollo=质量优先主力；Aion=快，去重复帧；Chronos=老版备选 |
| 输入帧率 | 24 | 视频原始帧率（和 LoadVideo 的 `force_rate` 一致） |
| 输出帧率 | 60 | 目标帧率，必须大于输入帧率（如 7→24、24→60） |
| 慢动作倍数 | 1.0 | 1.0=不慢放；2.0=时长翻倍的慢动作（会生成更多帧） |
| 并行实例 | 2 | 同卡并行加速，实测实例 2 比 1 快约 31%；双卡并列勿用 |
| 重复帧检测 | 开 | 检测并替换重复帧（rdt>0）；关=不去重（rdt 0） |
| 重复帧敏感性 | 5 | 1-100 滑块（≈GUI 同名滑杆），越大检出越多重复帧；内部 rdt=0.2×s/100，5=GUI默认(0.01)，100=最强 |
| 场景检测 | 关 | 硬切镜头处不做去重/插帧误判；多镜头素材建议开 |
| 输入质量 | 14 | 同星光节点（中间编码质量） |
| GPU选择 | Auto (自动) | 自动识别多显卡。Auto=ComfyUI 主卡(cuda:0，本机对应驱动枚举 1=4070TiS，与旧默认一致)；可手动选任意单卡。插帧用驱动枚举，内部自动换算（本机 GPU0=4060Ti、GPU1=4070TiS）。多卡(All GPUs)模式不稳定已停用，请只选单卡 |

### 插帧 vs 补帧（模型怎么选）

| | **Apollo 插帧** | **Aion 补帧** |
|---|---|---|
| 原理 | 相邻帧之间光流**生成全新中间帧** | **识别并剔除重复帧** + 局部光流重排，不凭空造运动 |
| 本质 | 增补：帧不够 → 造出来 | 梳理：帧"虚高/僵" → 变真流畅 |
| 速度 | 慢（约 Aion 的一半） | 快一倍 |
| 适合素材 | 低帧率动画/视频补流畅、慢动作 | 帧率虚高的素材（游戏录屏插帧过、重复帧凑数）、ComfyUI/Wan 生成的低帧率视频（7fps→24/60） |
| 记忆法 | 无中生有（造中间帧） | 去伪存真（去重复帧，让真实运动顺滑） |

> 两者都能改帧率、做慢动作。**一般素材（尤其 AI 生成视频）选 Aion 又快又合适；动画/卡顿录屏想补出丝滑新运动才上 Apollo。**
> 帧率虚高的判断：用播放器逐帧看，发现画面重复/呆滞（同一帧出现多次）就是重复帧——Aion 的主场。

### 注意事项

- 输出帧数估算：`输入帧数 ÷ 输入帧率 × 慢动作倍数 × 输出帧率`（如 14帧@7fps→24fps 约 48 帧，实测吻合）
- 首次用某分辨率会现场编译（约 30 秒 ~ 1 分钟），偶发一次崩溃会自动重试，第二次起即稳定
- 本机无 Intel 核显也能用（走 NVIDIA cuvid 硬解，与 GUI 同款参数）

### 多显卡

两个节点都带 **GPU选择** 下拉，自动识别所有 NVIDIA 卡并显示卡名（按 CUDA 顺序，和 ComfyUI 一致）：

- **Auto（默认）** = ComfyUI 主卡（cuda:0），与旧版本行为完全一致，单卡机器无需理会
- 双卡/多卡机器可手动选任意一张卡做超分或插帧
- 超分与插帧两个引擎的 GPU 枚举顺序相反，节点内部已自动换算，UI 上不用管编号差异
- **多卡并行（All GPUs）不提供**：实测双卡并行模式初始化异常慢且不稳定，已停用，请用单卡
- 若 ComfyUI 以 `--cuda-device N` 启动（会自动设 `CUDA_VISIBLE_DEVICES` 限制进程内 torch 可见卡），本插件仍会列出**全部**物理卡，且引擎子进程会自动清除该限制——选任意一张卡都能真正生效，无需改启动参数

## 七、常见问题

**Q：跑起来后工作流卡住不动？**
正常。星光处理几分钟到几十分钟，控制台有实时进度。

**Q：输出没有声音？**
节点输出的是纯画面帧；模板里音频已从 LoadVideo 旁路到 VideoCombine，正常会带上。若你改过连线，保持 `LoadVideo.audio → VideoCombine.audio` 这条线即可。

**Q：报错 "Topaz engine incomplete"？**
`topaz_engine/` 缺文件：检查 `neuroserver/`、`models/slp25/`（42 个 blob）、`tvmd/`（Topaz.lic + VR.lic）、`bin/`（ffmpeg.exe + ffprobe.exe）。

**Q：需要装 ffmpeg 吗？**
不需要。引擎包 `bin/` 已内置 ffmpeg 8.1.1（LGPL 开源，可随包分发），节点和引擎自动使用它；系统里装了也不冲突（内置版优先）。若你在别的节点（如 VHS）遇到 ffmpeg 报错，可在该节点设置里手动填 `topaz_engine\bin\ffmpeg.exe` 路径。

**Q：想先试通再全量跑？**
LoadVideo 里设 `frame_load_cap`（如 10），跑通后再放开。

**Q：想接入自己的 Wan 生成工作流？**
把星光节点 Ctrl+C/V 复制过去，把原来 `VHS_VideoCombine.images` 的输入线改为：
`出片帧 → 星光节点 → VideoCombine.images`，音频线不动。

## 八、引擎包（topaz_engine）说明

```
topaz_engine/
├── neuroserver171/  1.7.1 引擎（星光 2.6/2.6 + Astra 家族共用）
├── models/slp26/    星光 2.6 权重（7.4GB，"星光 2.6"条目即此）
├── models/astra*/   Astra 家族权重（astra/astrafast/astrahq/astrasharp）
├── tvmd/            授权目录（Topaz.lic + VR.lic + nyx-3 滤镜模型，勿删）
├── bin/             ffmpeg 8.1.1 全功能版（节点读写视频用，软解 h264）
├── bin171/          1.7.1 引擎配套 ffmpeg + 全部 DLL（引擎内部用，勿精简）
└── 使用说明.txt
```

- **自包含**：节点自动相对定位引擎，无注册表/环境变量/管理员依赖
- **ffmpeg 两套**：`bin/`（节点读写）与 `bin171/`（引擎内部，含 tvai_up 滤镜、禁软解）分工明确
- **迁移**：整个 ComfyUI 目录复制即可，目标机只需 NVIDIA 显卡（驱动支持 CUDA 12.8+）
- **注意**：Python/torch 版本锁定（模型代码为编译模块），不要自行升级；引擎升级走"换权重/换整个 neuroserver"路线

## 九、引擎自动识别（无需引擎包也能用）

节点启动时按优先级自动找引擎：

1. **打包引擎**：`ComfyUI/topaz_engine/`（本包，最稳）
2. **本机已装 Topaz**：读注册表 `InstallDir` + 常见路径自动识别（如 `D:\APP\topaz`、`C:\Program Files\Topaz Labs LLC\Topaz Video`），**借用其 neuroserver 与模型目录**

也就是说：**对方机器上已经装了 Topaz（正版或破解、能正常导出星光）→ 只需要一个几 KB 的节点文件夹，不用 18GB 引擎包**。
引擎来源会在控制台打印（`引擎: bundled` 或 `引擎: installed@...`），出错时也方便排查。

> 注意：借用模式使用对方自己的授权环境——对方 GUI 能导出星光，节点就能用；对方机器授权本身是坏的，节点也会报同样的授权错误（此时请用打包引擎模式）。
